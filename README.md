# XLAND — سایت معرفی و فروشگاه سرور

## ساختار فایل‌ها

همه فایل‌ها flat و کنار هم در یک پوشه هستند (بدون زیرپوشه‌ی css/ یا js/) — مناسب برای GitHub Pages:

```
xland/
├── index.html                  صفحه اصلی — کاملاً عمومی، بدون نیاز به لاگین
├── shop.html                   صفحه فروشگاه — کاملاً عمومی، بدون نیاز به لاگین
├── x89-manage-xland.html       پنل مدیریت — ورود با Firebase Authentication (آدرس عمداً غیرقابل‌حدس است)
├── style.css                   تمام استایل‌ها (شامل ریسپانسیو کامل)
├── data.js                     لایه داده — Firebase Realtime Database + localStorage به‌عنوان کش/fallback
├── common.js                   توابع مشترک همه صفحات (toast، لینک شبکه‌های اجتماعی، گوش‌دادن به آپدیت زنده)
├── effects.js                  فاز ۲/۳: ذرات متحرک، Tilt سه‌بعدی، Spotlight، نوار اسکرول، شمارنده اعداد
├── main.js                     رندر صفحه اصلی (هدر، آمار، تجهیزات، مپ، آی‌پی)
├── shop.js                     رندر کارت‌های محصول در فروشگاه
└── admin.js                    ورود/خروج با Firebase Auth + منطق پنل مدیریت
```

برای آپلود روی GitHub Pages: تمام این فایل‌ها را مستقیم در ریشه ریپازیتوری (یا پوشه‌ای که به‌عنوان Pages source انتخاب کرده‌ای) بگذار — نیازی به هیچ زیرپوشه‌ای نیست.

## نکته مهم: index.html و shop.html همیشه عمومی هستند

این دو صفحه هیچ‌وقت چک لاگین ندارند — کد ورود فقط داخل `x89-manage-xland.html` است.

## ورود به پنل مدیریت — حالا با Firebase Authentication واقعی

قبلاً ورود پنل یک سیستم نام‌کاربری/رمز محلی (فقط داخل مرورگر) بود. حالا واقعاً از **Firebase Authentication** استفاده می‌شود:

1. در Firebase Console پروژه‌ات (`xland-db`) برو به **Authentication → Sign-in method** و روش **Email/Password** را فعال کن (اگر هنوز فعال نیست).
2. در **Authentication → Users**، با دکمه «Add user» یک کاربر با ایمیل و رمز دلخواه خودت بساز — همین ایمیل/رمز از این به بعد اطلاعات ورود واقعی پنل است.
3. با همان ایمیل/رمز در `x89-manage-xland.html` وارد شو.

آدرس پنل: `آدرس-سایت-شما/x89-manage-xland.html` — عمداً در منو، فوتر یا هیچ‌جای دیگری از سایت لینک نشده.

اگر ورود با خطا مواجه شد، متن دقیق پیام Firebase (مثلاً «رمز اشتباه است» یا «چنین کاربری وجود ندارد») همان زیر فرم ورود نمایش داده می‌شود.

### تب «امنیت پنل» چه شد؟

طبق درخواستت چیزی حذف نشد — فرم قدیمی تغییر نام‌کاربری/رمز محلی (که رمز را با SHA-256 هش می‌کرد) همچنان در تب «امنیت پنل» وجود دارد. اما از این به بعد **این فرم دیگر اطلاعات ورود واقعی پنل را کنترل نمی‌کند** — چون ورود واقعی از طریق Firebase Authentication است. یک یادداشت زرد رنگ بالای همان تب این را به‌وضوح توضیح می‌دهد. برای تغییر ایمیل/رمز واقعی پنل، باید از Firebase Console → Authentication → Users اقدام کنی.

## ⚠️ تنظیم Firebase (Realtime Database)

هر سه فایل `index.html`، `shop.html` و `x89-manage-xland.html` از پروژه Firebase واقعی‌ات (`xland-db`) استفاده می‌کنند — مقادیر `firebaseConfig` در هر سه از قبل با اطلاعات واقعی که فرستادی پر شده‌اند، نیازی به ویرایش دستی نیست.

### 🚨 حتماً بخوان: قوانین (Rules) دیتابیس

پیش‌فرض Firebase در «حالت تست» به مدت ۳۰ روز به همه اجازه خواندن *و نوشتن* در Realtime Database را می‌دهد. حالا که Authentication واقعی داری، می‌توانی و باید Rules را طوری تنظیم کنی که فقط کاربر واردشده (ادمین) اجازه نوشتن داشته باشد؛ خواندن می‌تواند برای همه باز بماند (چون index.html/shop.html باید بدون لاگین قابل مشاهده باشند). نمونه Rules پیشنهادی در Firebase Console → Realtime Database → Rules:

```json
{
  "rules": {
    ".read": true,
    ".write": "auth != null"
  }
}
```

این یعنی: هرکسی می‌تواند سایت را ببیند، ولی فقط کسی که با Firebase Authentication وارد شده (یعنی از طریق پنل مدیریت لاگین کرده) می‌تواند چیزی در دیتابیس تغییر دهد. بدون این تنظیم، هر بازدیدکننده فنی می‌تواند مستقیماً از کنسول مرورگر روی دیتابیس بنویسد و محتوای سایت را برای همه خراب کند — این را جدی بگیر.

## آپلود روی Vercel / Netlify

هر دو سرویس از یک پوشه ساده HTML/CSS/JS بدون build پشتیبانی می‌کنند:

**Netlify:** وارد netlify.com شوید → "Deploy manually" → کل پوشه `xland` را drag & drop کنید.

**Vercel:** پروژه را در یک ریپازیتوری گیت‌هاب بگذارید یا از طریق `vercel deploy` داخل پوشه پروژه دیپلوی کنید. Framework Preset را روی **Other** بگذارید و Build Command را خالی رها کنید.

هیچ نصب npm یا build stepای لازم نیست.

⚠️ Firebase Auth و هش کردن رمز محلی هر دو به HTTPS نیاز دارند (هر آدرس Vercel/Netlify به‌صورت پیش‌فرض HTTPS است). برای تست محلی از یک سرور استاتیک ساده (مثل `npx serve`) استفاده کن، نه از باز کردن مستقیم فایل با `file://`.

## نحوه کار پنل مدیریت

پنل ۴ تب دارد:

1. **محصولات فروشگاه** — افزودن، ویرایش و حذف آیتم‌های فروشگاه (نام، قیمت به تومان، توضیحات، لینک تصویر، لینک خرید).
2. **سرور و شبکه‌های اجتماعی** — تغییر آی‌پی سرور و لینک دیسکورد/تلگرام/روبیکا/یوتیوب/آپارات. هر شبکه‌ای که لینکش خالی بماند، به‌صورت خودکار پنهان می‌شود.
3. **محتوای متنی سایت** — وضعیت سرور، عنوان بنر، توضیح زیر آن، عنوان و توضیح بخش تجهیزات و هر ۴ تجهیز، عنوان و متن بخش مپ خاورمیانه، و ۴ آمار بخش شمارنده.
4. **امنیت پنل** — فرم محلی قدیمی (توضیح داده شده در بالا)؛ برای تغییر واقعی ایمیل/رمز ورود، به Firebase Console مراجعه کن.

هر تغییری که ذخیره کنی، از طریق Firebase به‌صورت زنده روی `index.html` و `shop.html` — روی هر مرورگر یا دستگاهی — اعمال می‌شود، بدون نیاز به رفرش دستی.

## آیکون‌های شبکه‌های اجتماعی

آیکون‌ها اشکال ساده و عمومی هستند، نه لوگوی رسمی هر پلتفرم — این باعث می‌شود کاملاً سبک و یکدست بمانند.

## سفارشی‌سازی سریع

- رنگ‌ها و فونت‌ها: بالای `style.css` در بخش `:root`.
- مقادیر پیش‌فرض اولیه (برای وقتی Firebase هنوز داده‌ای ندارد): در `data.js` داخل `XLAND_DEFAULTS`.

## طراحی سه‌بعدی / نئونی (فاز ۲) و ریزه‌کاری‌ها (فاز ۳)

`effects.js` این‌ها را اضافه می‌کند (کاملاً بصری، بدون ارتباط با لاگین یا دیتابیس):

- **پس‌زمینه ذرات متحرک (Particle Canvas):** با موس و اسکرول واکنش نشان می‌دهد؛ روی موبایل سبک‌تر می‌شود.
- **افکت سه‌بعدی هنگام hover (Tilt) + Cursor Spotlight:** روی هر عنصر با کلاس `tilt-card`. روی موبایل/تبلت غیرفعال است.
- **ظهور هنگام اسکرول (Scroll Reveal):** بخش‌های پایین صفحه با کلاس `reveal`.
- **شمارنده اعداد (Count-Up):** بخش «آمار سرور» زیر هیرو، قابل ویرایش از تب «محتوای متنی سایت».
- **نوار پیشرفت اسکرول:** خط نازک نئونی بالای صفحه.

⚠️ بخش‌های مدیریت محصولات، سرور و محتوا در پنل دقیقاً همان‌طور که بودند باقی مانده‌اند — فقط سیستم ورود جایگزین شد.
